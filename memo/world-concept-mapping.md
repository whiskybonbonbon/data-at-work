# Data at Work — World Concept Mapping

これまで検討した技術概念と、作品世界における表現の対応表です。

「交通案内係」は使用せず、ルーターを自動制御された交差点として扱います。

| 技術・概念 | 世界観での表現 | 役割・注意点 |
|---|---|---|
| コンピュータネットワーク | 道路網 | 建物同士を接続する |
| ホスト | 住宅・店舗・業務ビル | 通信の出発地または目的地 |
| クライアント端末 | 一般住宅 | ユーザー操作によってデータが生まれる |
| サーバー | 店舗・業務ビル | 多数の依頼を受け付ける |
| データセンター | 大規模な業務地区 | 多数のサーバービルを収容する |
| データ | 荷物・情報の中身 | 処理、変換、保存、通信される |
| データちゃん | 荷物であり、都市を旅する主人公 | 物語上は連続した人格を持つ |
| IPアドレス | 建物の住所 | 通信先を識別する |
| ドメイン名 | 建物名・店舗名 | 人間が扱いやすい名前 |

## パケットの移動

| 技術・概念 | 世界観での表現 | 役割・注意点 |
|---|---|---|
| IPパケット | 宛先ラベル付き配送コンテナ | データとIPヘッダーを運ぶ |
| パケットヘッダー | 配送伝票 | 送信元、宛先などの制御情報を持つ |
| フレーム | 区間ごとの輸送車両 | EthernetやWi-Fiなど、リンクごとに作り直される |
| ペイロード | コンテナの中身 | 上位層から渡されたデータ |
| Ethernet | 有線道路の輸送方式 | 同一リンク内でフレームを運ぶ |
| Wi-Fi | 無線輸送区間 | 電波を利用してフレームを運ぶ |
| 光ファイバー | 光の高速輸送路 | ビットを光信号として伝える |
| 電気・光・電波 | 実際の移動を担う物理信号 | パケット自体が物理的な車として走るわけではない |
| TTL | 通過できる交差点数の上限 | ルーターを通過するたびに減少する |
| パケットロス | 配送コンテナの消失・受け入れ拒否 | 混雑や障害などで破棄される |
| 再送 | 同じ内容の荷物を再発送 | TCPなどが必要に応じて実現する |

## ルーターと交差点

| 技術・概念 | 世界観での表現 | 役割・注意点 |
|---|---|---|
| ルーター | 自動制御された交差点・ジャンクション | 宛先を確認して次の出口へ転送する |
| 入力インターフェース | 交差点の入口 | パケットが入ってくる |
| 出力インターフェース | 交差点の出口 | パケットを次の区間へ送り出す |
| ネクストホップ | 次の交差点 | 最終目的地ではなく、次の転送先 |
| ルートテーブル（RIB） | 管制室の詳細な道路台帳 | 学習した経路候補を保持する |
| 転送テーブル（FIB） | 実際の方面標識 | パケットをどの出口へ出すか決める |
| 最長プレフィックス一致 | 最も具体的な方面標識を優先する規則 | 宛先に最も細かく一致する経路を選ぶ |
| デフォルトルート | 「その他の方面」の標識 | 個別の経路がない場合に利用する |
| ルーティングプロトコル | 交差点間の道路情報網 | ルートテーブルを更新する材料を交換する |
| OSPF | 都市内部の道路情報交換システム | 組織内の経路計算に使われる |
| BGP | 都市・国家間の道路協定 | 異なるネットワーク間の経路を交換する |
| ACL | 通行許可ゲート | 条件に応じて通信を許可・拒否する |
| ファイアウォール | 検問所・警備ゲート | 通信を検査し、ポリシーに従って制御する |

## 標識と信号機

| 設備 | 対応する技術 | 具体的な役割 |
|---|---|---|
| 方面標識 | FIBのエントリー | 宛先ネットワークに対応する出口を示す |
| 標識の行き先 | IPプレフィックス | `192.168.1.0/24`などの宛先範囲 |
| 標識の矢印 | 出力インターフェース | パケットを送り出すポート |
| 次の交差点名 | ネクストホップ | 次に転送するルーター |
| 電子標識の更新 | FIBの更新 | 経路変更を実際の転送へ反映する |
| 信号待ちの車列 | 出力キュー | 送信を待つパケット |
| 信号制御装置 | パケットスケジューラー | 次に送信するキューやパケットを選ぶ |
| 青信号 | 送信許可 | 回線へパケットを送り出す |
| 赤信号 | キューで待機 | まだ送信順が来ていない |
| 優先信号 | QoS | 重要な通信を優先する |
| 車線満杯 | バッファ不足 | 新しいパケットを収容できない |
| 渋滞 | 輻輳 | 通信量が処理能力を上回る |

信号機は経路を決める設備ではありません。標識が「どこへ」、信号が「いつ送るか」を表します。

## GPU・CUDA

| 技術・概念 | 世界観での表現 | 役割・注意点 |
|---|---|---|
| GPU | 大規模並列演算工場・演算部隊 | 多数の計算を並列に処理する |
| CUDA | NVIDIA製GPU向けの指令体系・運用基盤 | GPUそのものではない |
| CUDA Core | 多数の演算作業員 | 実際の演算処理を担う |
| CUDA Kernel | 全作業員へ配られる作業指示 | GPU上で実行する関数 |
| CUDA Thread | 一人分の作業 | 個別の処理単位 |
| Block | 作業班 | 複数のスレッドをまとめる |
| Grid | 作戦全体 | 複数のブロックをまとめる |
| VRAM | GPU工場専用の作業場 | GPUが利用するデータを保持する |
| シェーダー | 描画・画像処理の専門作業指示 | GPUで実行されるプログラム |
| CPUからGPUへの依頼 | 本部から並列工場への発注 | CPU側がGPU処理を準備する |

CUDAは基本的にNVIDIAのGPUを対象とするプラットフォーム兼プログラミングモデルです。

## パケットが目的地へ届く流れ

| 段階 | 世界観での出来事 | 技術的な処理 |
|---:|---|---|
| 1 | 店舗や住宅で荷物が作られる | アプリケーションがデータを生成する |
| 2 | 配送コンテナへ入れる | TCP／UDPやIPの情報が付加される |
| 3 | 区間用の輸送車両へ積む | リンク層のフレームへ格納される |
| 4 | 道路を移動する | 電気、光、電波として伝送される |
| 5 | 交差点へ到着する | ルーターがフレームを受信する |
| 6 | 宛先ラベルを確認する | 宛先IPアドレスを読み取る |
| 7 | 方面標識を調べる | FIBを最長プレフィックス一致で検索する |
| 8 | 出口車線へ並ぶ | 出力キューへ格納される |
| 9 | 信号が変わる | スケジューラーが送信対象を選ぶ |
| 10 | 新しい車両へ積み替える | 次のリンク用フレームを作る |
| 11 | 次の交差点へ進む | 次のルーターへ送信する |
| 12 | 目的地の建物へ到着する | 対応するホストが受信する |
| 13 | 指定窓口へ届ける | ポートやソケットからプロセスへ渡す |

## 基本構造の要約

> 建物が通信の出発地と目的地、道路がネットワーク、ルーターが交差点、FIBが標識、キューとスケジューラーが信号制御、パケットが宛先付きの配送コンテナです。
